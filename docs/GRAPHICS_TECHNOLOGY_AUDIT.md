# Bedray Alpha 2 graphics technology audit

11 November 2026. Scope is Windows Vulkan and the current Bedray source. Evidence level L0.

## DLSS 5 Neural Rendering

The local NVIDIA-signed nvngx_dlssnr.dll 310.8.0.0 is x64 and exports Vulkan feature creation, evaluation, requirements and release. Bedray pins its SHA-256 to e16bcf15e16e13f527491cdf7845b2fe6521a738d8f7c9c721866a8496e1fc8e. Place it beside the nvngx_dlss.dll selected by Bedray and build vkb_dlss.dll with the updated bridge. The advanced DLSS 5 Neural Rendering slider stores dlss_neural_intensity in the super_resolution section. Its range is 0–100 and the default is 0.

The experimental route uses generic NVIDIA NGX Vulkan calls for feature 18, with display-referred SDR world color converted to RGBA16F, reversed-Z depth and render-resolution pixel motion. Its separate RGBA16F result feeds direct DLSS Super Resolution before the hand and UI. RR-owned frames, temporally resolved world color and the Streamline DLSS path bypass this route. The bridge reports the vendor result on rejection. A failed evaluation discards the containing command buffer and the next eligible frame uses ordinary DLSS. The full Neural Rendering SDK remains partner-access, so dispatch through the installed NGX core and the output contract need runtime confirmation for this exact DLL and driver. [NVIDIA technical overview](https://developer.nvidia.com/blog/whats-new-for-game-developers-dlss-5-with-3d-guided-neural-rendering-nvidia-ace-updates-and-new-rtx-kit-capabilities/) · [NVIDIA SDK access thread](https://forums.developer.nvidia.com/t/official-dlss-5-neural-rendering-plugin-access-for-unreal-engine-5-8-2/382731)

## Gaps worth tracking

| Gap | Current Vulkan status and work required |
|---|---|
| Motion and composition masks | The common temporal path mostly reconstructs motion from camera transforms and raster depth. RR can supply its own RT motion when available. The FidelityFX ABI has reactive and transparency/composition fields, but Bedray does not populate them. Produce motion for moving entities and animated geometry, and consistent masks for water, particles, transparency and emission. Feed the signals to SR, denoisers, FG and, once the NVIDIA contract is available, the Neural Rendering engine mask. This addresses temporal artifacts across vendors. [AMD FSR SDK manual](https://gpuopen.com/manuals/fsr_sdk/) |
| FSR 4 Vulkan frame generation | Bedray still uses its FSR 3 swapchain path. AMD SDK 2.4 exposes FSR FG 4.0.2 and its 4.0.0 swapchain through the signed Vulkan loader and framegeneration effect, with ML support on RX 9000 and up. Upgrade the swapchain/queue and prepare-dispatch integration as one change, including resize, present completion and teardown. [AMD FSR SDK 2.4](https://gpuopen.com/amd-fsr-sdk/) · [Frame generation API](https://gpuopen.com/manuals/fsr_sdk/techniques/frame-interpolation-api/) |
| Vulkan ray denoising on AMD | AMD FSR Ray Regeneration 1.2.1 and AMD Radiance Caching 0.9.0 currently ship only for D3D12. Bedray can keep improving its existing Vulkan denoising and reservoir paths for Radeon. [AMD FSR SDK 2.4](https://gpuopen.com/amd-fsr-sdk/) |
| Radiance cache in the native path tracer | NVIDIA RTXGI has Vulkan examples for NRC and SHaRC. NRC needs path-vertex data, training work and cache queries in the native tracing loop. Compare it with Bedray's existing ReSTIR and radiance-cache paths on indirect-light noise, GPU time and VRAM. [NVIDIA RTXGI NRC guide](https://github.com/NVIDIA-RTX/RTXGI/blob/main/Docs/NrcGuide.md) |
| Dynamic Multi Frame Generation | The current Streamline programming guide lists Dynamic MFG as D3D12-only. Bedray's Vulkan DLSS-G exposes fixed multipliers where supported by the driver and GPU. [NVIDIA Streamline guide](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS_G.md#63-enabling-dynamic-multi-frame-generation) |
| Intel frame generation and low latency | The public XeSS 3.0.2 SDK exposes Vulkan Super Resolution. Intel's XeSS-FG and XeLL guides currently specify D3D12. [XeSS SDK release](https://github.com/intel/xess/releases/tag/v3.0.2) · [Intel XeSS-FG guide](https://github.com/intel/xess/blob/main/doc/xess_fg_developer_guide_english.md) · [Intel XeLL guide](https://github.com/intel/xess/blob/main/doc/xell_developer_guide_english.md) |

FSR Upscaling 4.1.2 uses the signed AMD Vulkan loader and upscaler from SDK 2.4. The loader and effect must share a directory. This changes the upscaling provider path. FSR 3 frame generation has its own legacy loader and swapchain path. [AMD SDK integration instructions](https://gpuopen.com/amd-fsr-sdk/)
