# RR output reconstruction — 2026-11-03

The previous chain ran RR at input resolution and then DLSS SR over the result.
NVIDIA's [RR integration guide](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS_RR.md)
describes RR as the output reconstruction replacing SR. This change implements
that route for hardware Path Tracing + DLSS + initialized RR + frame generation
setting **OFF**. It does not establish a measured FPS/quality improvement.

## One plan before world recording

`WorldResolutionPlan` freezes the trace and world/presentation extents. Rays and
all RR input guides use the initialized DLSS provider's input extent; RR outputs
directly at window extent using the matching quality and low-resolution motion
flag. The same-size feature uses DLAA. No resolution setting is rewritten.

World rasterization runs at output resolution with an unjittered projection.
This keeps its depth, particles/weather and selected-block lines on the final
grid. Ray jitter remains on the input grid. This deliberately retains full-size
raster work instead of introducing an unproven hardware-depth upscale or feeding
UI into RR. Its cost versus the removed SR evaluation needs GPU measurement.
The existing DLSS context still supplies resolution policy; a separate RR-only
optimal-size query and removal of unused SR feature residency remain future work.

The first RR initialization frame retains the existing route. Other temporal
backends, debug views and FG-enabled configurations also keep it. The next frame
after successful initialization can use single RR output. A diagnostic switch,
`-Dbedray.rt.disableRrOutput=true`, retains the previous output route for A/B.

## Radiance, depth and post

The RR owner separately tracks input/output extents and output-feature quality.
Its composition runs over the output extent, including sky; it returns before
any smaller input-guide indexing. G-buffer and motion resources stay input-sized.

`RtFrameResources` keeps the raw input-sized display image/depth and an independent
output color/depth pair. Allocation completes before publishing a new generation;
every initialization/write is pinned through the host's exact recording proof.
Output-only resizes and changes back to the standard route are generation changes.

The AOT `output_resolve` pass transfers the nearest source depth onto an unjittered
output ray while preserving that sample's view depth. This is a resampled guide,
not geometry generated by the neural model. Invalid depth becomes the sky sentinel.
If RR skipped, the same pass fills the complete output image from the raw display
fallback. It records once through the existing native core; no new native ABI or
ray is introduced. Native-size RR also gets an independent depth target.

Particles/weather composite, bloom and volumetrics then use matching output-sized
color/depth. The engine receives a complete image before world post and selection.
End-of-world presentation copies it to main and does not dispatch SR. Unused SR
motion/depth targets are not resized and its raster-depth copy is skipped on this
route. First-person hands remain deferred and are replayed at full resolution.

## Temporal consistency and failure

Initialized RR is a jitter consumer even without an upscaler. Native RR therefore
uses temporal subpixel coverage at unchanged resolution. Entering/leaving jitter
mode resets RR history. All paths of an RR pixel share the primary ray; their
BSDF/light samples remain independent. Multiple SPP no longer averages unrelated
primary surfaces into a single RR normal/depth/material/motion guide.

An RR recording exception can follow emitted commands. The entire unsubmitted
command buffer is discarded, its exact retirement callbacks run, and the engine's
raster frame remains available. RR falls back next frame. A failed discard cleanup
still quarantines/fails the RT path. Native core failures keep their existing
whole-command discard policy. Engine target retirement now waits for native target
copies and subsequent same-queue work too.

`[VKB-RESOLVE]` logs trace/raster/output extents and FG condition when the plan
changes. RR feature logs contain requested/actual quality and input/output extent.
Recording failure logs identify discard and fallback rather than claiming a raw
RT image was submitted.

## Checks and open acceptance

The first integration passed 1150 Java tests (1141 passed, 9 skipped), 34 shim
checks and all 36 AOT entries. Production code `7556da0` with final discard tests
passed 1151 Java tests (1142 passed, 9 skipped), 34 shim checks and Windows CI
41559606231: candidate 125666752156, baseline 125666751920. Candidate includes
26 production Slang CPU signal/output-depth verdicts. These are L1/L2 checks.

GPU acceptance is still required for native RR, DLAA/Balanced/Quality, SPP 1/2/4,
resize, camera cuts, particles/weather, selection occlusion, moving entities,
glass/water/foliage and every enabled post effect. The new route has no local RTX
visual/FPS result. Single RR output with FG remains open: its producer guides and
constants must be migrated together before this guard is removed. Glass traversal,
many-light proposals and the other stack obligations are not completed by this PR.
