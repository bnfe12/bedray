## Fix before integrating the native core

1. **Descriptor set lifetime.** `native/bedray_core/src/core.cpp` allocates one
   set per program (`pool_info.maxSets = 1`) and updates that same set during
   `bedray_core_render_frame`. A later frame can mutate descriptors while an
   earlier recorded/submitted command buffer still references them. Multiple
   dispatches of the same program in one command buffer also reuse that set.
   Design per-dispatch or immutable/reusable descriptor allocations with
   explicit retirement based on host-proven GPU completion; per-frame slots
   alone are insufficient for multiple calls within the same frame.
2. **C ABI exception containment and cleanup.** `bedray_core_create` and
   `bedray_core_register_program` perform potentially throwing STL allocations
   outside their local `bad_alloc` handlers. In registration, Vulkan handles
   are created before later vector/map operations, so an exception can also
   bypass `destroy_program`. Use native RAII owners plus complete exception
   boundaries around every exported function that can throw. Preserve the C
   ABI and error mapping; no exception may escape to FFM.
3. **Frame completion and destruction.** `bedray_core_destroy_program` and
   `bedray_core_destroy` destroy Vulkan objects immediately. Define the host
   completion/teardown contract explicitly, including discarded or unsubmitted
   recordings, and defer release until every reference has completed. The
   separate `native/bedray_frame_lifetime` component is an unintegrated
   candidate, not an established ABI.
4. **Descriptor completeness.** `bedray_core_render_frame` validates each
   supplied binding, but does not require exactly one resource for every
   declared binding or reject duplicate resource bindings. This can dispatch
   with missing descriptors or reuse stale bindings from a previous call.
   Validate the full set before updating or recording any Vulkan commands.

## Align AOT integration with the user's direction

`gradle/slang.gradle` skips `compileSlang` without `slangc`; its comments and
`SlangPassLibrary` explicitly describe a legacy-GLSL fallback. The user directed
a new Slang/C++ renderer with no temporary legacy renderer path. Separate the
new renderer's artifact/build contract from any retained historical source:
require the toolchain and generated outputs whenever building the new renderer,
and report unsupported/missing resources clearly instead of claiming the new
renderer exists or silently loading a different shader path. Also track the
compiler binary/version and its arguments as build inputs: the task currently
tracks the Slang source directory and target profile, but not compiler identity.

## Shader algorithm correctness

1. **Voxel surface normal.** In `voxel/voxel.slang`, `traceMacro` initializes
   `normal` to zero on every macro entry. If the first voxel of an occupied
   macro is hit, the returned normal is zero, including entries at section and
   macro boundaries. `traversal/voxel_traversal.slang` uses that normal as
   both geometric and shading normal and builds a tangent frame from it. Carry
   the actual entry face through section/macro traversal and define the case
   where the ray starts inside a solid voxel. Avoid inventing an arbitrary
   normal when the ray has no well-defined entry face.
2. **Radiance Cascades angular rotation.** `radiance_cascades.slang` computes
   elevation from `(rayIndex + rotation) % rayCount`, while azimuth uses
   `radicalInverseVdC(rayIndex + rotation)` without the same wrap. For rotations
   crossing the boundary the original direction set is not merely permuted;
   verify the intended temporal sequence and its correspondence with stored
   interval/history addresses before allowing temporal reuse.
3. **ReSTIR PT candidate is incomplete.** The isolated agent's
   `ai-restir-pt/RESTIR_PT_NOTES.md` explicitly states reuse is biased, lacks
   suffix reconnection, skips environment visibility, can retain removed lights,
   and stores a mostly unused 304-byte record. Do not integrate or advertise
   this as unbiased complete ReSTIR PT. Request a design that provides correct
   shift mappings/Jacobians, visibility and invalidation, or explicitly label
   any approximation and its trade-offs.
4. **RC interval loss.** In the isolated `agent-rc-trace/.../rc_trace.slang`,
   `rcWalkRay` accumulates emissive translucent-surface contribution into
   `radianceNear`/`radianceFar`, then overwrites those values on a later opaque
   hit or environment miss. Preserve earlier contributions under the intended
   interval-composition model, and verify whether a far environment belongs
   in a bounded cascade interval before integration.
